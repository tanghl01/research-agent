# 智能体平台命名备忘录：法术体系

生成日期：2026-06-18  
用途：作为智能体平台品牌命名、产品模块命名与后续视觉/文案设计的参考备忘录。

---

## 1. 背景

原平台名称曾考虑使用“算子 / Operator”，其优点是具有“生长、演化、生态扩展”的隐喻，适合表达一个智能体平台从少量能力逐渐扩展为复杂生态系统的长期愿景。

但在面向普通用户和商业传播时，“算子”存在一定理解门槛：

- 词义略生僻；
- 第一反应不一定与 AI、工具、智能体能力相关；
- 可能带有生物、霉菌等联想；
- 作为用户侧产品名，亲和力和直观性略弱。

因此进一步讨论了“咒语、魔法、法术”等命名方向。

---

## 2. “咒语、魔法、法术”的对比

综合判断：

> **法术 > 咒语 > 魔法**

### 2.1 法术

“法术”最适合作为平台主命名方向。

它不像“魔法”那么泛，也不像“咒语”那么偏提示词，而更像一种可以被调用、编排、复用的专业能力单元。

这与平台定位高度吻合：

> 专业智能体平台 = 很多专家能力被封装成工作流、工具链、Agent App，用户按需调用。

适合的产品表达包括：

- 法术市场
- 法术库
- 法术编排
- 法术工坊
- 创建一个法术
- 调用一个科研综述法术
- 调用一个法律审查法术
- 调用一个投行估值法术

“法术”比“技能”更有想象力，比“工作流”更产品化，比“智能体”更容易被普通用户理解。

### 2.2 咒语

“咒语”更适合表示用户输入、Prompt 或口令，不太适合作为整个平台名。

它容易让人想到：

- 提示词
- Prompt 模板
- 万能咒语
- 输入一句话触发任务

但平台的核心不是简单 Prompt，而是：

> 工作流 + 工具调用 + 长任务执行 + 专业 Agent + 产物交付。

因此，“咒语”更适合作为入口层概念，而非平台主品牌。

可用于：

- 咒语模板
- 咒语库
- 咒语解析器
- 用户输入的任务需求

### 2.3 魔法

“魔法”最亲民、最轻松，但问题是太泛，容易显得像营销词或轻娱乐产品。

“魔法”适合用于营销表达，例如：

- 一键魔法
- AI 魔法
- 魔法生成

但不太适合作为专业智能体平台的核心品牌名。

原因是平台希望强调：

- 专业
- 稳定
- 工程化
- 可执行
- 可审计
- 专家级产出

“魔法”可能削弱这种专业感。

---

## 3. “法术”是否比“算子”更好

结论：

> **作为面向用户的产品名，“法术”整体上比“算子”更好。**

### 3.1 算子的优势

“算子”有较强的长期生态隐喻：

- 生长
- 繁殖
- 演化
- 生态扩张
- 平台能力不断增加

它更适合用于：

- 底层系统名称
- 技术品牌
- 开源项目
- 生态平台理念

### 3.2 算子的不足

作为用户侧产品名，“算子”的问题是：

- 不够直观；
- 用户不一定能立即理解其与 AI Agent 的关系；
- 商业传播时需要额外解释；
- 可能存在生物学联想偏差。

### 3.3 法术的优势

“法术”更容易被用户理解为一种“可调用能力”。

例如：

- 用户想做 PPT，可以调用一个 PPT 法术；
- 用户想审合同，可以调用一个合同审查法术；
- 用户想写论文，可以调用一个科研写作法术；
- 用户想做估值，可以调用一个投行估值法术。

这与平台核心能力高度一致：

> 把专业任务封装成一个个可调用、可复用、可编排的智能体能力。

### 3.4 建议

可以采用：

> **主品牌用“法术”，底层理念保留“算子”。**

例如：

> 法术 AI  
> 一个把专业工作流封装成可调用智能体能力的平台。  
> 每一个法术，都是一个可生长的专业智能体。

这样既保留了“算子”的进化感，又让用户第一眼能理解产品。

## 4. 核心命名体系

目前形成了一套较完整的产品隐喻体系：

| 产品概念 | 推荐命名 | 含义 |
|---|---|---|
| 用户 | 法师 | 使用平台、调用能力的人 |
| 智能体 / 技能 / 工作流 App | 法术 | 可调用、可复用的专业能力 |
| 积分 / 额度 / Token | 法力 | 调用法术所需消耗的资源 |
| 收藏的技能 / 个人能力库 | 法典 | 用户收藏、沉淀和管理法术的地方 |

核心表达为：

> **用户作为法师，调用法术完成任务，消耗法力，并将常用法术收藏进法典。**

这套命名体系的优点是：

- 统一；
- 好记；
- 有产品个性；
- 可扩展；
- 比“用户、技能、积分、收藏夹”更有品牌感；
- 与 AI Agent 的“能力封装、一键调用”特征吻合。

## 5. “法师 / 法术 / 法力 / 法典”的产品化设计

### 5.1 推荐保留的核心词

建议重点保留以下四个词：

> **法师 / 法术 / 法力 / 法典**

它们之间关系清晰，形成完整产品世界观。

### 5.2 可用于产品模块的命名

| 常规叫法 | 产品命名 |
|---|---|
| 用户 | 法师 |
| Agent / Workflow / Skill | 法术 |
| 积分 / 额度 | 法力 |
| 收藏夹 / 技能库 | 法典 |
| 技能市场 | 法术市场 |
| 用户自建技能 | 我的法术 |
| 官方模板 | 官方法术 |
| 行业技能包 | 法术套装 |
| 执行任务 | 施放法术 |
| 执行记录 | 施法记录 |
| 工作流编排器 | 法术编排器 |
| Agent Builder | 法术工坊 |

### 5.3 推荐首页表达

首页对外文案应保持专业，不宜过度玄幻。

推荐：

> **法术 AI：把专业工作流封装成可调用的智能体能力。**

或者：

> **把专家能力，封装成可调用的法术。**

或者：

> **面向专业任务的智能体法术平台。**

### 5.4 不建议过度使用的词

为了避免平台显得太游戏化、玄幻化，不建议在核心专业场景中过度使用：

- 魔导师等级
- 魔杖
- 召唤阵
- 黑魔法
- 禁咒
- 魔法学院
- 修炼法力

可采用“轻魔法隐喻 + 专业工具气质”的策略。

## 6. 关于“五行/元素系”命名

曾讨论：

- 工作流叫水系
- 智能体叫风系
- 技能叫木系

整体判断：

> **不建议把“水系、风系、木系”作为核心模块主名称。**

原因是它属于二级隐喻，理解成本较高。用户第一次看到“水系、风系、木系”时，很难立刻知道它们分别对应什么产品概念。

相比之下，“法师、法术、法力、法典”是一眼能懂的一级隐喻。

### 6.1 更合适的用法

“五行/元素系”可以作为分类标签、视觉系统、能力类型，而不是主导航名称。

例如：

| 产品概念 | 正式名称 | 可选元素标签 |
|---|---|---|
| 工作流 | 法术流 / 法术编排 / 法阵 | 水系 |
| 智能体 | 法灵 / Agent / 智能体 | 风系 |
| 工具 / 技能 | 技能 / 工具 / 法术组件 | 金系 |
| 知识库 / 文档 | 知识库 / 法典 / 知识树 | 木系 |
| 权限 / 安全 / 治理 | 权限 / 安全 / 治理 | 土系 |
| 算力 / 执行 / 生成 | 推理 / 执行 / 生成 | 火系 |

### 6.2 更推荐的元素对应关系

如果要使用元素体系，更建议：

| 元素 | 对应模块 | 理由 |
|---|---|---|
| 水系 | 工作流 / 流程编排 | 水流、流程、流转 |
| 风系 | 智能体 / 多 Agent 协作 | 灵活、游走、响应快 |
| 金系 | 工具 / 技能 / 执行器 | 工具、器物、结构、执行力 |
| 木系 | 知识库 / 文档 / 法典 | 生长、积累、知识树 |
| 土系 | 权限 / 安全 / 基础设施 | 稳定、边界、承载 |
| 火系 | 算力 / 推理 / 生成 | 能量、消耗、创造、运行 |

### 6.3 建议

不要把“水系、风系、木系”放在主导航上。

主导航仍建议使用专业清晰的命名：

- 法术市场
- 我的法典
- 法术工坊
- 法术编排
- 法力中心
- 施法记录

元素体系可以作为：

- 分类标签；
- 能力徽章；
- 视觉颜色系统；
- 法术类型；
- 市场筛选维度。

示例：

- 水系法术：流程编排类
- 风系法术：智能体协作类
- 金系法术：工具执行类
- 木系法术：知识沉淀类
- 火系法术：生成创作类
- 土系法术：安全治理类

## 8. 风格原则

为了避免“法术体系”显得过度玄幻，建议遵循以下原则：

### 8.1 名字可以有想象力，体验必须专业化

命名可以使用“法师、法术、法力、法典”，但界面、交互和产物要体现专业、可靠、工程化。

### 8.2 少用游戏化表达

可以轻度使用世界观，但不要把平台做成游戏社区或玄幻设定。

### 8.3 对外专业，对内有趣

对外首页、官网、融资材料、企业客户介绍中，应突出：

- 专业智能体；
- 工作流编排；
- 复杂任务执行；
- 专家级产物；
- 可复用能力；
- 行业解决方案。

产品内部可以保留更有趣的命名，例如：

- 我的法典
- 施放法术
- 法力余额
- 法术市场

### 8.4 视觉风格建议

建议采用：

- 现代科技感；
- 简洁扁平；
- 轻魔法符号；
- 不要厚重玄幻；
- 不要古风化；
- 不要游戏 UI 化。

可考虑的视觉关键词：

- 符文线条
- 能量流
- 几何法阵
- 深色科技背景
- 蓝紫渐变
- 简洁卡片
- 类 IDE / 工作台风格

## 9. 当前结论

当前最推荐的命名体系为：

> **平台：法术 AI**  
> **用户：法师**  
> **能力：法术**  
> **积分：法力**  
> **收藏 / 个人能力库：法典**

核心定位：

> **法术 AI 是一个面向专业任务的智能体平台，将专家工作流、工具链与 AI Agent 封装成可调用、可复用、可编排的“法术”。**

核心口号：

> **把专家能力，封装成可调用的法术。**

最终建议：

1. 主品牌优先使用“法术 AI”。
2. “算子”可作为底层技术理念或生态隐喻保留。
3. “法师 / 法术 / 法力 / 法典”可以形成完整产品体系。
4. “水系 / 风系 / 金系 / 木系 / 火系 / 土系”适合作为标签和视觉分类，不适合作为主导航。
5. 整体风格应是“轻魔法隐喻 + 专业智能体平台”，避免过度玄幻化。
